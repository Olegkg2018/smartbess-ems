## Что это

SmartBESS EMS — платформа для украинского BESS-накопителя, зарабатывающего на арбитраже цен рынка на добу наперед (РДН/DAM): прогноз цены (ML) → MILP-оптимизация графика заряд/разряд → диспетчеризация → SCADA-симуляция → финансовая отчётность для инвестора. Домен: Україна, `oree.com.ua` (Оператор ринку) как основной источник цен.

## Стек и структура

- Backend: FastAPI + SQLAlchemy, `app.py` — вход, `uvicorn app:app`, порт 5000 по умолчанию.
- Frontend: React 19 + Vite + TS в `frontend/`, роли Viewer/Operator/Manager/Admin, два воркспейса: **Dispatcher Console** (оперативная работа) и **Director Dashboard** (инвестор/руководитель).
- БД: sqlite локально (`data/smartbess.db`), Postgres/TimescaleDB в docker-compose для прод-подобного окружения. Схема — `Base.metadata.create_all` (`src/database/init_db.py`), без Alembic — новая модель применяется просто рестартом приложения.
- Ключевые модули backend:
  - `src/modules/forecast_service/ml_pipeline.py` — прогноз цены (LightGBM/XGBoost/MLP + LightGBM quantile P10/P90).
  - `src/modules/optimization_service/milp_model.py` — PuLP/CBC MILP-оптимизация графика батареи + Monte Carlo VaR.
  - `src/modules/market_data_service/data_manager.py` — сбор/кэш реальных данных (`oree.com.ua`, Open-Meteo).
  - `src/modules/external_data_service/` — `entsoe.py` (трансграничные перетоки + цена соседних зон), `intraday_market.py` (ВДР/IDM с oree), `gas_price.py` (index.minfin.com.ua), `telegram_public.py`/`telegram_bot.py` (публичные посты Укренерго/Мінэнерго как сигнал грид-стресса + алерты), `neighbor_weather.py` (погода PL/RO).
  - `src/modules/scada_service/` — симулятор Modbus-телеметрии + `soc_state.py` (цепочка приоритетов для стартового SoC).
  - `src/tasks/scheduler.py` — ежедневная джоба 17:30 (когда публикуется завтрашний РДН): sync данных → прогноз (LightGBM) → P10/P90 → MILP → сохранение плана.

## Как запускать/тестировать локально (грабли уже найдены — не наступать заново)

- Бэкенд: системный `python3` (fastapi/sqlalchemy стоят через `pip --user`). **`.venv` в репозитории НЕ имеет нужных зависимостей** — не использовать.
- Порт 5000 часто занят посторонним процессом (`~/energo/energy-prediction-ua`, другой проект) — проверять `ss -ltnp` перед тем как считать что-то этим репо; для ad-hoc тестов бэкенда использовать другой порт (напр. 5050).
- Frontend dev-сервер (`npm run dev`/vite) в этом WSL-окружении не поднимается: `node_modules` собран под Linux, но реально доступен только Windows `node.exe`. Компиляцию TS проверять через `"/mnt/c/Program Files/nodejs/node.exe" node_modules/typescript/bin/tsc --noEmit`. Это давняя проблема окружения, не чинить переустановкой node_modules без явного запроса.
- Авторизация — мок unsigned JWT (`alg: none`), собирается на клиенте (`frontend/src/api/client.ts::getMockToken`), роль — из claim `roles`. Для curl легко подделать base64url-скриптом.
- В коде/UI намеренно используется украинский язык (комментарии, докстринги, строки интерфейса) — это принятая конвенция проекта, не ошибка и не то, что нужно "исправлять".

## Главный принцип проекта: никаких выдуманных данных

Явное правило по всему коду ("не вигадувати", "не приймається на віру", "чесно NaN"): реальные данные и честный NaN на пробелах — никогда не константа-затычка или `np.random`. Раньше почти все "рыночные факторы" (Nuclear_Gen, Gas_Price, VDR_Volume, Grid_Import_Export и т.д.) были синтетическим шумом — это была главная причина плохого прогноза, всё заменено на реальные источники (см. MEMORY.md, раздел "Источники данных"). Новая фича идёт в продовый `FEATURES` только после `walk_forward_backtest`, и результат (даже отрицательный) документируется комментарием в коде, а не тихо выбрасывается.

## Продакшн-модель прогноза

Основная модель — **LightGBM** (`scheduler.py` всегда использует `predictions['lightgbm']`; XGBoost/MLP считаются параллельно и доступны в ручном запуске `/forecast/run` через `selected_model`, но не являются продовым выбором). P10/P90-интервал — отдельная LightGBM quantile-регрессия со split-conformal калибровкой на последних 60 днях (заменил вымышленное допущение ±1.64σ в риск-сценариях MILP). Подробности по фичам/экспериментам — MEMORY.md.

2. `git log --oneline` и `git status` — что реально закоммичено/незакоммичено локально.
