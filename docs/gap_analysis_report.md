# Звіт про розбіжності та статус реалізації (Gap Analysis Report)
## Проект: SmartBESS Ukraine (FastAPI + LightGBM Edition)

Цей звіт містить порівняльний аналіз поточної реалізації програмного забезпечення та вимог, викладених у 5 базових технічних специфікаціях (артефактах проектування).

---

## 1. Специфікація сбору даних (Data Ingestion & Integration Spec)
**Посилання на артефакт:** [bess_ingestion_specification.md](file:///home/oleg/.gemini/antigravity-cli/brain/c3e33046-4a7b-42cf-be90-0d52dffca2b3/bess_ingestion_specification.md)

*   **Виконано:**
    *   Асинхронний збір цін РДН безпосередньо з сайту ДП «Оператор ринку» (`oree.com.ua`) за допомогою `requests` та `BeautifulSoup` з механізмом повторних спроб (retries) та кешуванням місячних даних.
    *   Збір даних про погоду (температура, хмарність, вітер, радіація) через Open-Meteo API.
    *   Синхронізація та об'єднання (merge) історичних даних у єдиний файл для навчання моделей.
    *   Валідація пропущених значень та перевірка повноти бази даних (`verify_data_completeness`).
    *   **TimescaleDB Hypertables**: Успішно налаштовано збереження часових рядів у оптимізовані аналітичні гіпертаблиці.

*   **Не виконано / Потребує реалізації:**
    *   **Медальйонна архітектура (Medallion Architecture)**: Відсутній сирий рівень збереження (Bronze Layer) у сховище S3/MinIO. Дані завантажуються безпосередньо у базу даних або локальні `.csv`.
    *   **Парсинг за допомогою Playwright**: Не реалізовано парсинг складних HTML-сторінок (наприклад, тарифів НКРЕКП) за допомогою безголового браузера для обходу захисту Cloudflare.
    *   **Інтеграція ENTSO-E**: Ключ `ENTSOE_API_KEY` доданий у конфігурацію, але завантаження та врахування транскордонних перетоків потужності в моделі прогнозування не реалізовано.
    *   **Паттерн Circuit Breaker**: Немає автоматичного блокування запитів до збоящих зовнішніх сервісів для зменшення затримок.

## 2. Специфікація REST API (API Design Document)
**Посилання на артефакт:** [bess_api_specification.md](file:///home/oleg/.gemini/antigravity-cli/brain/c3e33046-4a7b-42cf-be90-0d52dffca2b3/bess_api_specification.md)

*   **Виконано:**
    *   Створено FastAPI сервер замість Flask із розділенням на API версії `v1` (`/api/v1/forecast/latest`, `/api/v1/scenarios/payback`, `/api/v1/optimization/plans`).
    *   Реалізовано обробники для сценарного аналізу окупності проекту та запуску прогнозування.
    *   Реалізовано ендпоінт перенавчання моделей `/api/retrain`.
    *   **Авторизація OAuth2 / OpenID Connect (OIDC)**: Повністю інтегровано перевірку JWT-токенів у заголовок Authorization (Bearer) на рівні FastAPI dependencies із підтримкою Keycloak JWKS сигнатур (RS256) та Mock Mode режиму.

*   **Не виконано / Потребує реалізації:**
    *   **Асинхронний трекінг задач (Celery)**: Замість повноцінної черги Celery/RabbitMQ фонові задачі симулюються за допомогою вбудованого модуля `threading` та планувальника APScheduler.
    *   **Веб-сокети для SCADA**: Потокова передача телеметрії батареї у реальному часі через `WebSocket` не реалізована.

## 3. Математична оптимізація BESS (MILP Optimization Design)
**Посилання на артефакт:** [bess_optimization_design.md](file:///home/oleg/.gemini/antigravity-cli/brain/c3e33046-4a7b-42cf-be90-0d52dffca2b3/bess_optimization_design.md)

*   **Виконано:**
    *   Модель MILP на базі **PuLP** та CBC-солвера успішно виконує оптимізацію добового графіку BESS.
    *   Враховано бінарне обмеження ($u_t \in \{0, 1\}$) для виключення одночасного заряду та розряду.
    *   Детально інтегровано тарифну сітку України (передача, розподіл, диспетцеризація, маржа постачальника).

*   **Не виконано / Потребує реалізації:**
    *   **Мультиринкова оптимізація**: Алгоритм працює тільки на ринку «на добу вперед» (РДН). Оптимізація для ВДР (внутрішньодобового ринку) та балансуючого ринку (БР) відсутня.
    *   **Динамічна деградація ячейок**: Вартість деградації (LCOS) задана як константа (`1.20 грн/кВт-год`), тоді як специфікація вимагає динамічного розрахунку залежно від температури осередків та глибини циклу (DoD).
    *   **Шифрований Modbus TCP (TLS)**: Симулятор SCADA працює за стандартним незахищеним Modbus TCP.

## 4. Специфікація фронтенду (UI/UX & Frontend Spec)
**Посилання на артефакт:** [bess_frontend_design_spec.md](file:///home/oleg/.gemini/antigravity-cli/brain/c3e33046-4a7b-42cf-be90-0d52dffca2b3/bess_frontend_design_spec.md)

*   **Виконано:**
    *   Реалізовано інтерфейси для більшості екранів: Executive Overview, Asset Detail, Price Forecast, Optimization Schedule, ROI, Settings & Tariffs.
    *   Інтегровано графіки цін, оптимального профілю SoC, а також сценарного аналізу ризиків.
    *   Додано можливість коригування ринкових факторів прогнозу безпосередньо з інтерфейсу.
    *   **Аналітичний C-Level Дашборд**: Повністю перероблено екран Executive Overview. Замість статичного прогнозу на одну добу він тепер відображає історичну прибутковість за днями YTD (з дати запуску BESS, що налаштовується в Settings) з урахуванням 80% точності прогнозування цін (моделювання зрізу неідеальних заявок) та фактичних даних телеметрії SCADA, а також будує траєкторію окупності проекту (Payback Trajectory) від початкового CAPEX до точки беззбитковості (Break-Even) із прогнозом до кінця року (ROY).
    *   **Ручне диспетчерування та переоцінка заявок**: Створено інтерактивну почасову таблицю на екрані Optimization Schedule. Оператори можуть вручну задавати час/потужність заряду/розряду та ціну прийнятої заявки. Дані зберігаються у гіпертаблиці `manual_overrides` в TimescaleDB та використовуються для підрахунку реального прибутку BESS. Таблиця і графіки інтегровані в єдиний реактивний цикл: будь-яке ручне введення одразу оновлює графік заряду/розряду, рівень SoC батареї в реальному часі та сумарні добові KPI (Дохід, Витрати, Знос, Чистий прибуток).
    *   **Водопадний графік добової доходності (Waterfall Arbitrage P&L)**: На ExecutiveOverview замість лінійного графіка реалізовано ComposedChart: зелені стовпчики показують дохід від продажу, червоні стовпчики (спрямовані вниз) — витрати на заряд та тарифи, а блакитна лінія — чистий прибуток BESS.
    *   **Персистентні налаштування**: Налаштування системи (включаючи OCP, ємність, потужність, ККД та дату початку роботи) зберігаються на сервері в `system_settings.json` та автоматично завантажуються на фронтенді при вході. Зміна дати початку роботи викликає автоматичне скидання аналітичного кешу.

*   **Не виконано / Потребує реалізації:**
    *   **Оновлення в реальному часі**: Дані завантажуються лише при зміні дати чи моделі. Немає підтримки WebSockets для відображення миттєвої телеметрії (напруга, SoC, температура) з Modbus-симулятора.
    *   **Повноцінний інтерфейс аудиту**: Екран "Audit / Model Decisions" відображає локальний статичний лог замість завантаження подій аудиту з бази даних.

## 5. Стандарт безпеки (Enterprise Security Baseline)
**Посилання на артефакт:** [bess_security_baseline.md](file:///home/oleg/.gemini/antigravity-cli/brain/c3e33046-4a7b-42cf-be90-0d52dffca2b3/bess_security_baseline.md)

*   **Виконано:**
    *   Реалізовано інтерфейс для принципу подвійного підтвердження (Four-Eyes Principle Workflow) при відправці команд на BESS.
    *   Розділено ролі користувачів (Viewer, Operator, Manager, Admin) у локальному стані фронтенду з обмеженням доступу до ручних дій.
    *   **Увімкнено TimescaleDB**: Робоча база даних мігрувала на TimescaleDB (образ `timescale/timescaledb:latest-pg16`). Всі часові ряди (ціни, прогнози, телеметрія, плани) автоматично конвертуються у гіпертаблиці для кращої швидкості аналітичних запитів.
    *   **Реальний аутентифікований Four-Eyes Principle / RBAC**: Реалізовано перевірку ролей (Viewer, Operator, Manager, Admin) на рівні API роутів за допомогою класів RoleChecker.

*   **Не виконано / Потребує реалізації:**
    *   **Управління секретами через HashiCorp Vault**: Всі ключі та події зчитуються з локального файлу конфігурації `.env` та змінних оточення Docker.
    *   **Криптографічний ланцюжок логування аудиту (SHA-256 Chain)**: База даних записує події аудиту у звичайні рядки PostgreSQL, без зв'язування хэшу поточного запису з попереднім для запобігання фальсифікації.
