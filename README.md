# SmartBESS EMS (Energy Management System) 🇺🇦

Промислова програмна платформа (EMS) для прогнозування цін на Ринку на добу вперед (РДН) в Україні, автоматичної математичної оптимізації графіків роботи систем накопичення енергії (BESS) та оперативного ручного керування (Manual Dispatch).

Платформа реалізує інтегрований цикл: збір цін -> AI-прогнозування -> MILP-оптимізація -> SCADA/Modbus симуляція телеметрії -> YTD фінансова звітність.

---

## 🌟 Основні можливості платформи

### 1. 📈 Фінансовий C-Level Дашборд (YTD / ROY Analytics)
*   **Траєкторія окупності**: Динамічний розрахунок накопичувального NPV проекту від початкового CAPEX до точки беззбитковості (Break-Even) із прогнозом окупності до кінця року (ROY).
*   **Реалістичне моделювання**: Розрахунок добової прибутності YTD враховує коефіцієнт неідеальності подачі заявок (80% успішності), тарифи ОСР та системну деградацію батареї (LCOS).
*   **Автоматичний кеш**: Звіти прискорюються за допомогою кешування в Redis та локального JSON-кешу на сервері.

### 2. ⚡ Математична MILP-оптимізація BESS (PuLP / CBC)
*   Цільова функція максимізує прибуток арбітражу: $\text{Revenue} - \text{Charging Cost} - \text{Tariffs} - \text{Battery Wear}$.
*   **Бінарні обмеження (Binary Constraints)**: Одночасне заряджання та розряджання батареї фізично унеможливлено.
*   **Врахування тарифної сітки**: Розрахунок включає тарифи НЕК «Укренерго» на передачу, диспетчеризацію, тарифи ОСР (1 або 2 клас напруги) та маржу постачальника.

### 3. 🛠️ Ручне диспетчеризування (Manual Overrides & Dispatch)
*   Інтерактивна почасова таблиця на 24 години на екрані **Optimization Schedule**.
*   Можливість вручну скоригувати потужність BESS (заряд/розряд у МВт) та реальну ціну заявки.
*   **Реактивність**: Будь-яке ручне введення одразу в реальному часі перераховує криву SoC, зарядні бари та добові показники (Дохід, Витрати, Амортизація зносу).
*   Дані зберігаються у гіпертаблиці бази даних TimescaleDB.

### 4. 🖧 SCADA та Modbus TCP Симулятор
*   Вбудований фоновий симулятор батареї: Modbus TCP сервер на порту `5020`.
*   Фізична симуляція зносу, тепловиділення, обмежень струму та рівня SoC.
*   EMS клієнт автоматично зчитує телеметрію та записує керуючі команди кожну хвилину.

## 🛠️ Технологічний стек

*   **Backend**: Python 3.11, FastAPI (асинхронний веб-сервер), SQLAlchemy (ORM), PuLP & CBC Solver (MILP оптимізація), PyModbus (SCADA симулятор).
*   **Frontend**: React 18, Vite, TypeScript, Recharts (професійна фінансова аналітика), Lucide React (іконки), Преміальний Custom CSS дизайн.
*   **Database & Cache**: TimescaleDB (PostgreSQL 16) — автоматично створює гіпертаблиці часових рядів; Redis — для швидкого кешування стану.

## 🚀 Встановлення та запуск

Платформа повністю контейнеризована і запускається однією командою.

### 1. Системні вимоги
*   Встановлений **Docker** та **Docker Compose**.
*   Мінімум 4 ГБ оперативної пам'яті.

### 2. Клонування та запуск
```bash
# Перейдіть у директорію проекту та запустіть контейнери
docker compose up --build -d
```

### 3. Перевірка статусу контейнерів
```bash
docker compose ps
```
Ви повинні побачити чотири працюючі контейнери:
*   `smartbess-db` (TimescaleDB на порту `5432`)
*   `smartbess-redis` (Redis на порту `6379`)
*   `smartbess-platform` (FastAPI + React на порту `5000` хост-машини, SCADA Modbus на `5020`)

### 4. Доступ до інтерфейсу
Відкрийте браузер та перейдіть за адресою:
👉 **[http://localhost:5004](http://localhost:5004)** або **[http://localhost:5000](http://localhost:5000)**

Для автентифікації на фронтенді використовується вбудований симульований Keycloak JWT-токен. Ви можете змінювати ролі у правому верхньому кутку (`Viewer`, `Operator`, `Manager`, `Admin`), щоб перевірити обмеження безпеки та правила Four-Eyes Principle.

## 📊 Основні REST API ендпоінти
*   `GET /api/v1/reports/executive-summary?asset_id=<id>` — Отримання YTD фінансової аналітики та NPV окупності.
*   `GET/POST /api/v1/optimization/settings` — Збереження/завантаження технічних параметрів BESS та дати запуску.
*   `GET/POST /api/v1/optimization/manual-overrides` — Керування ручним диспетчеризуванням.
